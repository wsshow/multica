This documentation describes the customized edition. Use this checkout or artifacts supplied by your deployment maintainer; upstream application packages do not contain these changes.

## Build or obtain the customized package

Install a package produced from a reviewed customized commit or supplied by your maintainer. When preparing your own package, use the workspace scripts below; Go and platform build/signing prerequisites are required. These documentation commands do not imply that a build has been performed.

```bash
pnpm install --frozen-lockfile
pnpm --filter @multica/desktop package
```

## Required server configuration

Both `apiUrl` and `appUrl` are required. The web URL is used for browser login and share links; it is not guessed from the API host. Store valid JSON as `~/.multica/desktop.json` (Windows: `%USERPROFILE%\.multica\desktop.json`). On Windows, use UTF-8 and ensure the filename is not `desktop.json.txt`. Restart the app after changes.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

The Compose example binds host ports to `127.0.0.1`. For remote access, use a TLS reverse proxy and set your own `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS`, and upload URL. `localhost` in Desktop means the Desktop computer. Replace example addresses when Docker runs elsewhere. Configure the appropriate auth, health, and WebSocket routes; verify from the execution computer.

## Tabs and the local runtime

Desktop reuses the shared web pages and maintains tabs per workspace. After sign-in it starts its bundled customized CLI in a profile scoped to the configured API. It does not select a system CLI or download an upstream replacement. Agent tools, their authentication, and their model quota remain external requirements. Settings show daemon status and logs.

Switching between Board, List, Table, Swimlane, and Gantt in a tab also keeps each view's latest scroll position, including the board's horizontal position and scrolling within its columns.

Logging out clears every tab saved on the machine, so the next person to sign in never sees pages left behind by the previous account.

## Operator-owned update sources

Updates are disabled until `updateUrl` names your own generic Electron update feed. Optional `links.docsUrl`, `links.changelogUrl`, `links.downloadUrl`, `links.communityUrl`, and `links.feedbackUrl` select your help destinations; omitted links are hidden. `links.cliInstallUrl` and `links.cliInstallWindowsUrl` can publish your own CLI installers. `links.runtimeReleaseUrl` selects standalone runtime release metadata. Desktop-managed runtimes never query a CLI release source. Never repair a missing bundled CLI with an upstream package.

If a manual check or download fails, Settings shows a short message and a **Retry** button. You can keep using the current version while retrying.

## Voice input

Desktop can transcribe speech into chat, comments, replies, and descriptions when creating issues on your computer. Voice input is **off by default** and isn't available in the web app.

1. Open **Settings → Voice input** and turn on **Voice input**.
2. Download a speech model for the languages you use. Downloads need an internet connection; transcription runs locally once the model is installed. If the page reports that on-device transcription is unavailable, this build has no usable speech engine on your computer.
3. Allow microphone access when prompted. You can choose and test the microphone on the same settings page.

The default **Tap or hold** mode offers two ways to dictate: click the mic to start, then click the checkmark to insert the text; or hold the mic while speaking and release it to insert. Inserting leaves the text in the editor for you to review. In chat and comments, the send button in the recording bar, or `Enter` while that bar is recording, transcribes and sends. `Esc` cancels.

The voice shortcut is **unassigned by default**. Set it under **Settings → Shortcuts**; it works while a supported editor is visible, even without focus. You can also choose tap-only or hold-only activation under **Voice input**.

### Recordings and history

Audio is transcribed on this computer without being uploaded for transcription. Text you send is submitted as an ordinary chat message or comment.

Recordings and transcripts are kept locally for **30 days by default**. Under **Settings → Voice input → History**, you can play recordings, copy text, retry transcription, delete entries, or clear everything. **Keep history** offers no retention, 1 day, 7 days, 30 days, or forever.

Turning off **Voice input** hides the mic and disables its shortcut. It does not delete recordings already saved; history remains accessible on the same page.
