Cette documentation concerne l’édition personnalisée. Utilisez ce checkout ou les artefacts fournis par votre responsable de déploiement ; les paquets applicatifs du projet d’origine ne contiennent pas ces modifications.

## Préparer un paquet personnalisé

Installez un paquet issu d’un commit personnalisé validé ou fourni par votre responsable. Pour construire le vôtre, utilisez les scripts ci-dessous avec Go et les outils de construction/signature de la plateforme. Ces commandes documentaires ne signifient pas qu’une compilation a été exécutée.

```bash
pnpm install --frozen-lockfile
pnpm --filter @multica/desktop package
```

## Configuration de connexion obligatoire

`apiUrl` et `appUrl` sont obligatoires. L’URL Web sert à la connexion par navigateur et au partage ; elle n’est pas déduite de l’hôte API. Enregistrez du JSON UTF-8 dans `~/.multica/desktop.json`, ou `%USERPROFILE%\.multica\desktop.json` sous Windows. Évitez l’extension `.txt` et redémarrez après modification.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

L’exemple Compose lie les ports à `127.0.0.1`. Pour un accès distant, utilisez un proxy inverse TLS et configurez vos propres `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS` et URL de fichiers. Dans Desktop, `localhost` désigne l’ordinateur Desktop. Configurez les routes d’authentification, de santé et WebSocket, puis vérifiez depuis l’ordinateur d’exécution.

## Onglets et exécution locale

Desktop réutilise les pages partagées et conserve les onglets par espace de travail. Après connexion, il démarre le CLI personnalisé inclus dans un profile propre à l’API configurée. Il ne choisit pas un CLI système et ne télécharge pas de binaire du projet d’origine. Outils d’agent, authentification et quota de modèle restent à préparer. Les réglages affichent état et journaux.

## Vos propres sources de mise à jour

Les mises à jour exigent `updateUrl` pointant vers votre flux Electron générique. Les liens d’aide utilisent `links.docsUrl`, `links.changelogUrl`, `links.downloadUrl`, `links.communityUrl`, `links.feedbackUrl` ; les liens absents sont masqués. Vos installateurs CLI et métadonnées utilisent `links.cliInstallUrl`, `links.cliInstallWindowsUrl`, `links.runtimeReleaseUrl`. Les runtimes gérés par Desktop ne consultent jamais les versions CLI. Si le CLI inclus manque, reconstruisez ou réinstallez le paquet Desktop personnalisé.
