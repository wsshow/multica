Cette documentation concerne l’édition personnalisée. Utilisez ce checkout ou les artefacts fournis par votre responsable de déploiement ; les paquets applicatifs du projet d’origine ne contiennent pas ces modifications.

## Préparer un paquet personnalisé

Installez un paquet issu d’un commit personnalisé validé ou fourni par votre responsable. Pour construire le vôtre, utilisez les scripts ci-dessous avec Go et les outils de construction/signature de la plateforme. Ces commandes documentaires ne signifient pas qu’une compilation a été exécutée.

```bash
pnpm install --frozen-lockfile
pnpm --filter @multica/desktop package
```

## Configuration de connexion obligatoire

Au premier lancement, saisissez l’URL de votre service intégré. Desktop l’enregistre comme adresse d’API et adresse Web. Si l’API et l’application Web utilisent des adresses distinctes, configurez le fichier ci-dessous.

`apiUrl` et `appUrl` sont obligatoires. L’URL Web sert à la connexion par navigateur et au partage ; elle n’est pas déduite de l’hôte API. Enregistrez du JSON UTF-8 dans `~/.multica/desktop.json`, ou `%USERPROFILE%\.multica\desktop.json` sous Windows. Évitez l’extension `.txt` et redémarrez après modification.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

L’exemple Compose lie les ports à `127.0.0.1`. Pour un accès distant, utilisez un proxy inverse TLS et configurez vos propres `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS` et URL de fichiers. Dans Desktop, `localhost` désigne l’ordinateur Desktop. Configurez les routes d’authentification, de santé et WebSocket, puis vérifiez depuis l’ordinateur d’exécution.

## Onglets et exécution locale

Desktop réutilise les pages partagées et conserve les onglets par espace de travail. Après connexion, il démarre le CLI personnalisé inclus dans un profile propre à l’API configurée. Il ne choisit pas un CLI système et ne télécharge pas de binaire du projet d’origine. Outils d’agent, authentification et quota de modèle restent à préparer. Les réglages affichent état et journaux.

Quand vous passez d’une disposition à l’autre dans un onglet (Tableau, Liste, Grille, Couloirs ou Gantt), chacune conserve sa position de défilement. Dans le tableau, vous retrouvez aussi la même colonne à l’écran et la même position dans chaque colonne.

La déconnexion efface tous les onglets enregistrés sur la machine : la personne suivante qui se connecte ne voit jamais les pages laissées par le compte précédent.

## Vos propres sources de mise à jour

Les mises à jour exigent `updateUrl` pointant vers votre flux Electron générique. Les liens d’aide utilisent `links.docsUrl`, `links.changelogUrl`, `links.downloadUrl`, `links.communityUrl`, `links.feedbackUrl` ; les liens absents sont masqués. Vos installateurs CLI et métadonnées utilisent `links.cliInstallUrl`, `links.cliInstallWindowsUrl`, `links.runtimeReleaseUrl`. Les runtimes gérés par Desktop ne consultent jamais les versions CLI. Si le CLI inclus manque, reconstruisez ou réinstallez le paquet Desktop personnalisé.

Si une vérification manuelle ou un téléchargement échoue, les réglages affichent un court message et un bouton **Réessayer**. Vous pouvez continuer à utiliser la version actuelle pendant ce temps.

## Saisie vocale

Desktop peut transcrire votre voix sur cet ordinateur pour remplir les chats, commentaires, réponses et descriptions lors de la création de tâches. La saisie vocale est **désactivée par défaut** et n'est pas disponible dans l'application web.

1. Ouvrez **Paramètres → Saisie vocale** et activez **Saisie vocale**.
2. Téléchargez un modèle vocal adapté aux langues que vous utilisez. Le téléchargement nécessite une connexion Internet ; une fois le modèle installé, la transcription s'effectue localement. Si la page indique que la transcription sur l'appareil est indisponible, cette version de l'application n'a pas de moteur vocal utilisable sur cet ordinateur.
3. Autorisez l'accès au micro lorsque la demande apparaît. Vous pouvez aussi choisir et tester le micro sur cette page.

Le mode par défaut **Appui ou maintien** permet de cliquer sur le micro pour commencer, puis sur la coche pour insérer le texte, ou de maintenir le micro enfoncé pour parler et de le relâcher pour insérer. Le texte reste dans l'éditeur pour que vous puissiez le relire. Dans les chats et les commentaires, le bouton d'envoi de la barre d'enregistrement, ou `Enter` pendant l'enregistrement dans cette barre, transcrit puis envoie. `Esc` annule.

Le raccourci vocal est **non défini par défaut**. Attribuez-le dans **Paramètres → Raccourcis** ; il fonctionne dès qu'un éditeur compatible est visible, même sans le focus. La page **Saisie vocale** permet aussi de choisir une activation par appui seul ou maintien seul.

### Enregistrements et historique

La transcription s'effectue sur cet ordinateur, sans envoyer l'audio à un service de transcription. Le texte que vous envoyez est soumis comme un message de chat ou un commentaire ordinaire.

Les enregistrements et transcriptions sont conservés localement **30 jours par défaut**. Dans **Paramètres → Saisie vocale → Historique**, vous pouvez écouter les enregistrements, copier le texte, relancer la transcription, supprimer une entrée ou tout effacer. **Conserver l'historique** propose de ne rien conserver, ou de conserver les entrées 1 jour, 7 jours, 30 jours ou toujours.

Désactiver **Saisie vocale** masque le micro et désactive son raccourci. Les enregistrements déjà sauvegardés ne sont pas supprimés ; l'historique reste accessible sur la même page.
