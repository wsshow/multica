title: カスタム版のセルフホスト
description: カスタムソースから Docker サービスを構築し、Desktop と配布元を設定します。
---

この文書はカスタム版向けです。現在のソース、または運用担当者が提供した成果物を使用してください。上流のアプリ配布物にはこの変更は含まれません。

## ソースの準備

レビュー済みのカスタム checkout または管理者のソースアーカイブを使います。この版に公開配布リポジトリは設定されていません。Docker Compose プラグイン、Make、OpenSSL を用意します。エージェントツールとアカウントは実行端末で別途準備します。

## サービスの起動

リポジトリのルートで実行します。初回は `.env` がない場合だけ設定と初期シークレットを生成し、このソースから `multica-backend:dev` と `multica-web:dev` を構築して PostgreSQL、API、Web を起動します。既存の設定とボリュームは維持されます。既存シークレットを確認してください。

```bash
make selfhost-build
docker compose -f docker-compose.selfhost.yml ps
curl -fsS http://localhost:8080/readyz
```

Web: `http://localhost:3000` · API: `http://localhost:8080`

## ログイン

自分の Web URL を開き、メール確認コードでログインします。本番のメール配信には自分の SMTP または Resend と送信ドメインが必要です。未設定の場合、現在のバックエンドは生成コードをログに出します。固定コードは `APP_ENV=development` 専用です。公開環境では使わないでください。Google ログインには自分の OAuth 設定が必要です。

## Desktop の接続

カスタム Electron パッケージを使い、`apps/desktop/desktop.example.json` を `~/.multica/desktop.json` にコピーして両方の URL を編集し、再起動します。未設定では接続しません。任意の `wsUrl` で API から生成する WebSocket URL を上書きできます。

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

## 別の実行端末の接続

同じカスタムソースから CLI を構築し、そのバイナリを PATH に置いて明示的に接続します。Desktop は CLI を同梱するため、管理対象ランタイム用の別インストールは不要です。実行端末にはログイン済みの対応エージェントツールが必要です。

```bash
go -C server build -o bin/multica ./cmd/multica
```

```bash
multica setup self-host --server-url http://localhost:8080 --app-url http://localhost:3000
multica auth status
multica daemon status
```

## リモートアクセス

Compose のホストポートは `127.0.0.1` にバインドされます。リモート接続では TLS リバースプロキシと、自分の `FRONTEND_ORIGIN`、`MULTICA_APP_URL`、`MULTICA_PUBLIC_URL`、`CORS_ALLOWED_ORIGINS`、アップロード URL を設定します。Desktop の `localhost` は Desktop の端末です。認証、ヘルスチェック、WebSocket の経路を設定し、実行端末から確認してください。

## バックアップと更新

PostgreSQL、アップロード、シークレット、配布リビジョンをバックアップします。ソース配備ではレビュー済みのカスタムコミットに移動し `make selfhost-build` を実行します。自分の公開済みイメージを使う場合は `MULTICA_BACKEND_IMAGE`、`MULTICA_WEB_IMAGE`、不変の `MULTICA_IMAGE_TAG` を指定して `make selfhost` を使います。このコマンドは取得のみでソースを構築しません。上流の `latest` を更新元にしないでください。イメージの巻き戻しだけでは DB マイグレーションは戻りません。

```bash
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > multica-backup.sql
```

## Kubernetes

`deploy/helm/multica` のソース chart と自分のイメージを使い、`values.yaml` に従って Secret を先に作成します。全ノードでイメージを取得可能にします。既定はローカル `:dev` と `IfNotPresent` です。再起動だけでは更新されません。上流 OCI chart は不要です。

```bash
helm upgrade --install multica ./deploy/helm/multica --namespace multica
```

## 確認

`/readyz`、ログイン、ランタイム登録、タスク結果、添付を確認します。`/health` は生存確認のみです。テレメトリ、クラッシュ送信、匿名送信、運用メトリクスは無効です。`/metrics` と `/health/realtime` は使えません。画面の使用量、コスト、履歴、オンライン状態は維持されます。

```bash
make selfhost-stop
```
