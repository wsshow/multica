이 문서는 맞춤 버전용입니다. 현재 소스 또는 배포 관리자가 제공한 산출물을 사용하세요. 원본 프로젝트의 앱 배포물에는 이 변경 사항이 없습니다.

## 개인 인스턴스 시작

Docker Compose 2.30 이상을 준비하고 [저장소 설치 스크립트](https://github.com/wsshow/multica/blob/main/docs/integrated-image.md#personal-deployment)로 최신 안정 버전을 설치합니다. 터미널에 표시된 주소(기본값 `http://localhost:8080`)를 열고 일회용 설정 코드를 입력합니다. 관리자 계정을 만들면 개인 워크스페이스가 열립니다.

Docker Compose가 PostgreSQL을 관리하며 첨부 파일과 서명 키는 로컬에 저장됩니다. 환경 파일이나 메일 서비스는 필요하지 않습니다. 현재 소스에서 빌드하고 시작하려면 `make integrated-personal-build`를 실행합니다.

## 소스 준비

검토된 맞춤 checkout 또는 관리자가 제공한 소스 압축 파일을 사용합니다. Docker Compose 플러그인, Make, OpenSSL이 필요합니다. 에이전트 도구와 계정은 실행 컴퓨터에 별도로 준비합니다.

## 서비스 시작

저장소 루트에서 실행합니다. `.env`가 없을 때만 설정과 초기 비밀값을 만들고 현재 소스로 `multica-backend:dev`, `multica-web:dev`를 빌드하여 PostgreSQL, API, Web을 시작합니다. 기존 설정과 볼륨은 유지합니다. 기존 비밀값을 먼저 확인하세요.

```bash
make selfhost-build
docker compose -f docker-compose.selfhost.yml ps
curl -fsS http://localhost:8080/readyz
```

Web: `http://localhost:3000` · API: `http://localhost:8080`

## 로그인

자체 Web 주소를 열고 이메일 인증 코드로 로그인합니다. 운영용 메일은 직접 설정한 SMTP 또는 Resend와 발신 도메인이 필요합니다. 메일 제공자가 없으면 현재 백엔드는 생성 코드를 로그에 표시합니다. 고정 코드는 `APP_ENV=development`에서만 사용하고 공개 배포에서는 사용하지 마세요. Google 로그인에는 자체 OAuth 설정이 필요합니다.

## Desktop 연결

맞춤 Electron 패키지를 사용하고 `apps/desktop/desktop.example.json`을 `~/.multica/desktop.json`으로 복사해 두 주소를 수정한 뒤 재시작합니다. 설정이 없으면 연결하지 않습니다. 선택적인 `wsUrl`은 API에서 생성되는 WebSocket 주소를 덮어씁니다.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

## 다른 실행 컴퓨터 연결

같은 맞춤 소스로 CLI를 빌드하고 그 바이너리를 PATH에 넣어 명시적으로 연결합니다. Desktop에는 CLI가 포함되어 관리되는 runtime을 위한 별도 설치는 필요 없습니다. 실행 컴퓨터에는 로그인된 지원 에이전트 도구가 있어야 합니다.

```bash
go -C server build -o bin/multica ./cmd/multica
```

```bash
multica setup self-host --server-url http://localhost:8080 --app-url http://localhost:3000
multica auth status
multica daemon status
```

## 원격 접속

Compose의 호스트 포트는 `127.0.0.1`에 바인딩됩니다. 원격 접속은 TLS 리버스 프록시와 자체 `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS`, 업로드 URL을 설정하세요. Desktop의 `localhost`는 Desktop 컴퓨터를 의미합니다. 인증, 상태 확인, WebSocket 경로를 설정하고 실행 컴퓨터에서 검증합니다.

## 백업과 업그레이드

PostgreSQL, 업로드, 비밀값과 배포 리비전을 백업합니다. 소스 배포는 검토된 맞춤 커밋으로 전환하고 `make selfhost-build`를 실행합니다. 자체 게시 이미지를 사용하면 `MULTICA_BACKEND_IMAGE`, `MULTICA_WEB_IMAGE`, 불변 `MULTICA_IMAGE_TAG`를 설정하고 `make selfhost`를 실행합니다. 이 명령은 이미지를 가져오며 소스를 빌드하지 않습니다. 원본 `latest`로 맞춤 버전을 덮어쓰지 마세요. 이전 이미지만 실행해도 DB 마이그레이션은 되돌아가지 않습니다.

```bash
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > multica-backup.sql
```

## Kubernetes

소스 chart `deploy/helm/multica`와 자체 이미지 저장소를 사용하고 `values.yaml`에 따라 Secret을 먼저 만듭니다. 모든 노드가 이미지를 가져올 수 있어야 합니다. 기본은 로컬 `:dev`와 `IfNotPresent`이므로 재시작만으로 버전이 바뀌지 않습니다. 원본 OCI chart는 필요 없습니다.

```bash
helm upgrade --install multica ./deploy/helm/multica --namespace multica
```

## 검증

`/readyz`, 로그인, runtime 등록, 작업 결과, 첨부 파일을 검증합니다. `/health`는 프로세스 생존만 확인합니다. 텔레메트리, 충돌 보고, 익명 보고, 운영 지표는 비활성화되어 `/metrics`와 `/health/realtime`은 사용할 수 없습니다. 화면의 사용량, 비용, 기록, 온라인 상태는 유지합니다.

```bash
make selfhost-stop
```
