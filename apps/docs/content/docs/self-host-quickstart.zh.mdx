本文适用于定制版本。使用当前定制源码或部署维护者提供的产物；上游应用安装包不包含这些修改。

## 启动个人实例

准备 Docker Compose 2.30+，用[仓库安装脚本](https://github.com/wsshow/multica/blob/main/docs/integrated-image.zh.md#个人部署)安装最新稳定版。打开 `http://localhost:8080`，输入终端显示的一次性初始化码，创建管理员账号后进入个人工作区。

Docker Compose 自动管理 PostgreSQL，附件和签名密钥保存在本地。启动时无需准备环境文件或邮件服务。从当前源码构建并启动可用 `make integrated-personal-build`。

## 准备源码

使用经过审查的定制 checkout，或维护者提供的源码包。准备 Docker Compose 插件、Make 和 OpenSSL。执行电脑上的智能体工具和账号另行安装与登录。

## 启动服务

在仓库根目录运行。首次使用时，命令仅在 `.env` 不存在时创建配置并生成初始密钥，再从当前源码构建 `multica-backend:dev`、`multica-web:dev`，启动 PostgreSQL、API 和 Web。已有配置和数据卷会保留；部署前检查已有文件中的密钥。

```bash
make selfhost-build
docker compose -f docker-compose.selfhost.yml ps
curl -fsS http://localhost:8080/readyz
```

Web: `http://localhost:3000` · API: `http://localhost:8080`

## 登录

打开自己的 Web 地址，创建账号和工作区，使用邮箱验证码登录。生产环境需要配置自己的 SMTP 或 Resend 及发件域名；未配置邮件服务时，当前后端会在日志中输出生成的验证码。固定开发验证码仅适用于 `APP_ENV=development`，不要用于公开部署。Google 登录需要配置自己的 OAuth。

## 连接桌面端

安装当前源码构建或维护者发布的定制 Electron 包。将 `apps/desktop/desktop.example.json` 复制到 `~/.multica/desktop.json`，修改两个地址后重启。缺少配置时不会连接；可选的 `wsUrl` 用于覆盖根据 API 地址生成的 WebSocket 地址。

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

## 连接其他执行电脑

从同一份定制源码构建 CLI，将该二进制加入 PATH，再显式连接。桌面端已经内置 CLI，其托管运行时不需要另行安装。执行电脑仍需安装并登录一款受支持的智能体工具。

```bash
go -C server build -o bin/multica ./cmd/multica
```

```bash
multica setup self-host --server-url http://localhost:8080 --app-url http://localhost:3000
multica auth status
multica daemon status
```

## 远程访问

Compose 示例只绑定主机的 `127.0.0.1`。跨机器访问时使用带 TLS 的反向代理，并配置自己的 `FRONTEND_ORIGIN`、`MULTICA_APP_URL`、`MULTICA_PUBLIC_URL`、`CORS_ALLOWED_ORIGINS` 和上传地址。桌面端的 `localhost` 指桌面端所在电脑；Docker 在其他机器时需要替换示例地址。正确转发认证、健康检查和 WebSocket，并从执行电脑验证。

## 备份和升级

先备份 PostgreSQL、上传文件、密钥和部署版本。源码部署切换到经过审查的定制提交，再运行 `make selfhost-build`。使用已发布的定制镜像时，显式填写 `MULTICA_BACKEND_IMAGE`、`MULTICA_WEB_IMAGE` 和不可变的 `MULTICA_IMAGE_TAG`，再运行 `make selfhost`；该命令拉取配置的镜像，不会构建当前源码。不要用上游 `latest` 覆盖定制版本。只回退容器镜像不会撤销数据库迁移。

```bash
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > multica-backup.sql
```

## Kubernetes

使用源码中的 `deploy/helm/multica`，配置自己的镜像仓库、标签，以及 `deploy/helm/multica/values.yaml` 要求的 Secret。每个集群节点都必须能取得镜像。chart 默认为本地 `:dev` 镜像和 `IfNotPresent`；只重启工作负载不会升级版本，不需要使用上游 OCI chart。

```bash
helm upgrade --install multica ./deploy/helm/multica --namespace multica
```

## 验证

验证 `/readyz`、登录、运行时注册、任务执行和附件。`/health` 只说明进程存活。产品遥测、崩溃上报、匿名上报和运维指标已禁用，`/metrics`、`/health/realtime` 不可用；界面使用的用量、成本、执行历史和运行时在线状态仍然保留。

```bash
make selfhost-stop
```
