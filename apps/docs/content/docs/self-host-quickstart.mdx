This documentation describes the customized edition. Use this checkout or artifacts supplied by your deployment maintainer; upstream application packages do not contain these changes.

## Start a personal instance

From the customized checkout, run `make integrated-personal INTEGRATED_IMAGE=your-namespace/multica:X.Y.Z` with a published integrated image from your maintainer. Open `http://localhost:8080` and enter the one-time code printed in your terminal. Set your username and password to open your personal workspace.

Docker Compose manages PostgreSQL and stores uploads and signing keys locally. You can start without an environment file or mail service. For an image built from this checkout, use `make integrated-personal-build`.

## Prepare the source

Start from the reviewed customized checkout or a source archive supplied by its maintainer. No public replacement repository is configured. Install Docker with the Compose plugin, Make, and OpenSSL. Agent tools and their accounts are installed separately on execution computers.

## Start the services

Run at the repository root. On first use, this creates `.env` and initial secrets if missing, builds `multica-backend:dev` and `multica-web:dev` from this source, and starts PostgreSQL, backend, and frontend. Existing configuration and volumes are reused. Inspect existing secrets before deployment.

```bash
make selfhost-build
docker compose -f docker-compose.selfhost.yml ps
curl -fsS http://localhost:8080/readyz
```

Web: `http://localhost:3000` · API: `http://localhost:8080`

## Sign in

Open your web app, create an account/workspace, and use email verification. Production email delivery needs your own SMTP or Resend settings and sender domain. Without a mail provider, the current backend logs generated codes. A fixed development code requires `APP_ENV=development`; do not enable it on a public deployment. Google login requires your own OAuth configuration.

## Connect Desktop

Use the customized Electron package from this checkout or your maintainer. Copy `apps/desktop/desktop.example.json` to `~/.multica/desktop.json`, edit both URLs, and restart Desktop. Missing settings block connection. Optional `wsUrl` overrides the socket URL otherwise derived from the configured API.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

## Connect another computer

Build the CLI from this same customized source, put that binary on PATH, then connect explicitly. Desktop already bundles its CLI; its managed runtime needs no separate installation. A supported agent tool must be installed and signed in on the execution computer.

```bash
go -C server build -o bin/multica ./cmd/multica
```

```bash
multica setup self-host --server-url http://localhost:8080 --app-url http://localhost:3000
multica auth status
multica daemon status
```

## Remote access

The Compose example binds host ports to `127.0.0.1`. For remote access, use a TLS reverse proxy and set your own `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS`, and upload URL. `localhost` in Desktop means the Desktop computer. Replace example addresses when Docker runs elsewhere. Configure the appropriate auth, health, and WebSocket routes; verify from the execution computer.

## Updates and backups

Back up PostgreSQL, uploaded files, secrets, and the deployed source/image revision. For source deployments, select a reviewed customized commit and rerun `make selfhost-build`. For published customized images, set `MULTICA_BACKEND_IMAGE`, `MULTICA_WEB_IMAGE`, and an immutable `MULTICA_IMAGE_TAG`, then use `make selfhost`. That target pulls configured images; it does not build this checkout. Do not use upstream `latest` artifacts as an upgrade. An older container image alone does not undo migrations.

```bash
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > multica-backup.sql
```

## Kubernetes

Use the source chart at `deploy/helm/multica`, your own image registry/tags, and a pre-created Secret as described in `deploy/helm/multica/values.yaml`. Images must be available to every cluster node. The chart defaults to local `:dev` images with `IfNotPresent`; a rollout restart is not a version upgrade. No upstream OCI chart is required.

```bash
helm upgrade --install multica ./deploy/helm/multica --namespace multica
```

## Verification

Verify `/readyz`, login, runtime registration, task completion, and attachments. `/health` is liveness only. Product telemetry, crash reporting, anonymous reporting, and operational metrics are disabled; `/metrics` and `/health/realtime` are unavailable. User-facing usage, costs, history, and runtime liveness remain functional.

```bash
make selfhost-stop
```
