第一次设备或 Release 构建前，将 `apps/mobile/.env.production.example` 复制为已忽略的 `apps/mobile/.env.production.local`，将 `EXPO_PUBLIC_API_URL` 和 `EXPO_PUBLIC_WEB_URL` 都改成自己的部署。移动端有独立环境配置，桌面端配置不会替它设置地址。不要带着继承的公开服务地址构建，使用当前定制 checkout 或维护者提供的源码包。

Multica iOS 客户端目前还没有上架 App Store。你可以在 Mac 上从维护者提供的定制源码构建 Release 版本，再安装到自己的 iPhone。Android 客户端暂未提供。

定制 App 连接构建前填写的 API 和 Web 地址，账号与工作区数据属于该部署，不会自动选择公开服务。

## 准备工作

你需要：

- 一台安装了 Xcode 的 Mac；
- 已在 **Xcode → Settings → Accounts** 中登录的 Apple ID；
- 一台通过 USB 连接的 iPhone；
- 在 iPhone 的**设置 → 隐私与安全性**中打开开发者模式；
- Node.js、pnpm 和 Git。

Xcode 或真机开发环境未配置时，先完成 Expo 的 [iOS Device 环境配置](https://docs.expo.dev/get-started/set-up-your-environment/)。

## 安装到 iPhone

<Steps>
<Step>
克隆仓库并安装依赖：

```bash
# Run from the customized repository root.
pnpm install
```
</Step>
<Step>
从仓库根目录运行：

```bash
pnpm ios:mobile:device:prod:release
```

这会构建一个不依赖 Metro 的 Release 版本，并安装到已连接的 iPhone。第一次构建需要下载 iOS 依赖并编译 React Native，之后会复用 Xcode 缓存。
</Step>
<Step>
在 iPhone 上打开 App。如果系统阻止打开，到**设置 → 通用 → VPN 与设备管理**中信任对应的开发者证书。
</Step>
</Steps>

## 免费签名的 7 天限制

免费 Apple ID 签名的 App 只能使用 7 天。到期后，把 iPhone 重新连接到 Mac，并再次运行同一条构建命令即可续签。

Apple Developer Program 账号签名的有效期更长，也可以用于 TestFlight 和正式分发。无论使用哪种签名，服务端数据都不会因为重新安装或续签而丢失。

## 签名失败

如果 Xcode 提示 `No matching provisioning profiles found`，默认 bundle identifier 可能不属于你的 Apple ID。换成自己控制的反向域名后重新构建：

```bash
export EXPO_BUNDLE_IDENTIFIER_PROD=com.yourname.multica
pnpm ios:mobile:device:prod:release
```

这个值只需要在你的 Apple Developer team 中可用，不影响 Multica 账号或工作区。

## 更新

iOS 自助安装版不会自动更新。拉取最新代码、更新依赖并重新构建：

```bash
pnpm install
pnpm ios:mobile:device:prod:release
```

## 连接自托管实例

以 `apps/mobile/.env.production.example` 为模板，在已忽略的 `apps/mobile/.env.production.local` 中填写自己的两个服务地址。这与桌面端配置独立。使用 iPhone 可访问的地址，手机的 `localhost` 不是服务器。重新构建或升级前，先选择经过审查的定制提交。签名、真机构建和开发模式见当前 checkout 的 `apps/mobile/README.md`。

```dotenv
EXPO_PUBLIC_API_URL=https://api.example.com
EXPO_PUBLIC_WEB_URL=https://app.example.com
```

```bash
pnpm ios:mobile:device:prod:release
```
