이 문서는 맞춤 버전용입니다. 현재 소스 또는 배포 관리자가 제공한 산출물을 사용하세요. 원본 프로젝트의 앱 배포물에는 이 변경 사항이 없습니다.

## 맞춤 패키지 준비

검토된 소스로 만든 패키지나 관리자가 제공한 맞춤 패키지를 사용합니다. 직접 만들 때는 다음 스크립트와 Go, 대상 플랫폼의 빌드 및 서명 환경이 필요합니다. 문서의 명령은 실제 빌드가 수행되었다는 뜻이 아닙니다.

```bash
pnpm install --frozen-lockfile
pnpm --filter @multica/desktop package
```

## 필수 서비스 설정

`apiUrl`과 `appUrl`은 모두 필수입니다. Web URL은 브라우저 로그인과 공유에 사용되며 API 호스트에서 추측하지 않습니다. UTF-8 JSON을 `~/.multica/desktop.json`, Windows에서는 `%USERPROFILE%\.multica\desktop.json`에 저장하세요. `.txt` 확장자를 붙이지 말고 수정 후 앱을 재시작합니다.

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://localhost:8080",
  "appUrl": "http://localhost:3000"
}
```

Compose의 호스트 포트는 `127.0.0.1`에 바인딩됩니다. 원격 접속은 TLS 리버스 프록시와 자체 `FRONTEND_ORIGIN`, `MULTICA_APP_URL`, `MULTICA_PUBLIC_URL`, `CORS_ALLOWED_ORIGINS`, 업로드 URL을 설정하세요. Desktop의 `localhost`는 Desktop 컴퓨터를 의미합니다. 인증, 상태 확인, WebSocket 경로를 설정하고 실행 컴퓨터에서 검증합니다.

## 탭과 로컬 실행

공유 페이지를 재사용하며 작업 공간별 탭을 유지합니다. 로그인하면 설정된 API 전용 profile에서 포함된 맞춤 CLI를 시작합니다. 시스템 CLI를 선택하거나 원본 바이너리를 내려받지 않습니다. 에이전트 도구 인증과 모델 사용량은 따로 준비합니다. 설정에서 상태와 로그를 볼 수 있습니다.

## 직접 관리하는 업데이트 출처

`updateUrl`에 자체 일반 Electron 피드를 설정해야 업데이트가 활성화됩니다. 도움말은 `links.docsUrl`, `links.changelogUrl`, `links.downloadUrl`, `links.communityUrl`, `links.feedbackUrl`로 지정하고 누락된 링크는 숨깁니다. 자체 CLI 배포는 `links.cliInstallUrl`, `links.cliInstallWindowsUrl`, `links.runtimeReleaseUrl`을 설정합니다. Desktop 관리 runtime은 CLI 릴리스를 조회하지 않습니다. 포함된 CLI가 없으면 맞춤 Desktop 패키지를 다시 설치하거나 빌드하세요.
